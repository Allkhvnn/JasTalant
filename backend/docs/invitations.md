# Приглашения и доступ родителей

Администратор академии приглашает тренеров и родителей по email. Самостоятельно
назначить себе роль через API нельзя. `SUPER_ADMIN` также может управлять
приглашениями любой академии.

## API приглашений

| Метод | URL | Доступ | Назначение |
|---|---|---|---|
| POST | `/api/academies/{academyId}/invitations` | ADMIN | Создать и отправить приглашение |
| GET | `/api/academies/{academyId}/invitations?page=0&size=20` | ADMIN | Список приглашений |
| DELETE | `/api/academies/{academyId}/invitations/{id}` | ADMIN | Отозвать приглашение |
| POST | `/api/invitations/preview` | публичный | Проверить токен и показать форму |
| POST | `/api/invitations/accept-new` | публичный | Создать пользователя и принять приглашение |
| POST | `/api/invitations/accept` | авторизованный | Принять приглашение существующим пользователем |

Приглашение тренера:

```json
{"email":"coach@example.kz","roles":["COACH"],"playerIds":[]}
```

Приглашение родителя обязательно содержит хотя бы одного ребёнка:

```json
{
  "email":"parent@example.kz",
  "roles":["PARENT"],
  "playerIds":["UUID игрока"]
}
```

Можно передать обе роли: `COACH` и `PARENT`. Роль `ADMIN` через этот API не
назначается. Все игроки должны принадлежать академии из URL.

Письмо содержит ссылку `{FRONTEND_URL}/accept-invitation?token=...`. Локально
письмо открывается в Mailpit на http://localhost:8025. `FRONTEND_URL` по умолчанию
равен http://localhost:5173.

Токен состоит из 43 URL-safe символов, действует 72 часа и используется один раз.
В БД хранится только SHA-256 токена. Одновременно разрешено одно активное
приглашение на пару академия/email. Истёкшее приглашение автоматически отзывается
при создании нового. Сбой SMTP откатывает создание приглашения.

Preview принимает `{"token":"токен-из-ссылки"}` и возвращает название академии,
роли, срок и маскированный email. Новый пользователь принимает приглашение так:

```json
{
  "token":"токен-из-ссылки",
  "fullName":"Имя пользователя",
  "password":"длинный-уникальный-пароль"
}
```

Email берётся из приглашения и считается подтверждённым. Если аккаунт уже
существует, API возвращает 409: пользователь должен войти и вызвать
`/api/invitations/accept` с телом `{"token":"..."}`. Email вошедшего пользователя
обязан совпадать с приглашением.

## Родители и дети

| Метод | URL | Доступ | Назначение |
|---|---|---|---|
| GET | `/api/academies/{academyId}/parent/players` | PARENT | Только свои дети |
| GET | `/api/academies/{academyId}/parent/players/{playerId}` | PARENT | Карточка своего ребёнка |
| GET | `/api/academies/{academyId}/parent/players/{playerId}/attendance` | PARENT | История посещаемости ребёнка |
| PUT | `/api/academies/{academyId}/parents/{userId}/players/{playerId}` | ADMIN | Добавить связь |
| DELETE | `/api/academies/{academyId}/parents/{userId}/players/{playerId}` | ADMIN | Удалить связь |

Назначение из приглашения создаёт связь автоматически. Повторное назначение
идемпотентно. Родитель не получает доступ к общему `/players` и не может увидеть
чужого ребёнка по известному UUID. Удаление роли PARENT, членства или игрока
удаляет соответствующую связь на уровне БД.

История посещаемости поддерживает `page` и `size`, выводится от новых тренировок
к старым и содержит дату, группу, статус и комментарий тренера.

В MVP связь создаёт администратор. Подтверждение вторым родителем, документы об
опеке и журнал изменений пока не реализованы.
