# Почта: локальная разработка, демонстрация и закрытый пилот

| Режим | Профили Spring | Почта |
|---|---|---|
| Локальная разработка | `local` | Mailpit, http://localhost:8025 |
| Демонстрация и закрытый пилот | `local,smtp` | Gmail SMTP, реальные адресаты |

Локальный запуск: `docker compose up -d --wait`, затем
`.\gradlew.bat bootRun --args='--spring.profiles.active=local'` из папки `backend`.
Compose запускает БД и Mailpit. Профиль `local` явно использует localhost:1025
без SMTP-аутентификации, независимо от заполненных Gmail-переменных в `.env`.
Чтобы переключить режим, остановите backend и запустите его с нужными профилями.

Профиль `smtp` подключает реальный SMTP, без Mailpit. По умолчанию: `smtp.gmail.com`,
порт `587`, SMTP-аутентификация и обязательный STARTTLS с проверкой имени сервера.
Профиль `local` нужен вместе с ним для загрузки `backend/.env` и локальной PostgreSQL.

## Что настроить вручную в Google

1. Включите [двухэтапную аутентификацию](https://myaccount.google.com/security).
2. Откройте [пароли приложений](https://myaccount.google.com/apppasswords),
   создайте пароль с названием `JasTalant`.
3. В `backend/.env` заполните **существующие** строки:

```properties
SMTP_USERNAME=your-address@gmail.com
SMTP_PASSWORD=your-google-app-password
```

Укажите полный адрес Gmail и 16-символьный пароль приложения без разделительных
пробелов, не пароль Google-аккаунта. Кавычки вокруг значений не нужны.
Не отправляйте пароль в чат и не добавляйте `.env` в Git.
Существующие `DB_PASSWORD` и `JWT_SECRET_BASE64` сохраните.
Если строки SMTP уже есть, измените их, не добавляйте дубликаты.

Адрес отправителя по умолчанию совпадает с `SMTP_USERNAME`. Если `MAIL_FROM` уже
задан, замените его на этот же Gmail-адрес или подтверждённый в Google адрес
отправителя. Например, `no-reply@jastalant.local` для реальной почты не подходит.

Справка Google: [пароли приложений](https://support.google.com/accounts/answer/185833?hl=ru),
[параметры SMTP](https://support.google.com/mail/answer/7104828?hl=ru).
Если создание пароля приложения недоступно, проверьте ограничения аккаунта,
двухэтапную аутентификацию и политики организации по инструкции Google.

## Демонстрация и закрытый пилот: запуск в PowerShell

```powershell
cd C:\Users\Sam\Desktop\Backend\backend
docker compose up -d --wait postgres
$env:JAVA_HOME = 'C:\Program Files\Eclipse Adoptium\jdk-21.0.9.10-hotspot'
$env:Path = "$env:JAVA_HOME\bin;$env:Path"
.\gradlew.bat bootRun --args='--spring.profiles.active=local,smtp'
```

Профиль `smtp` указывайте **после** `local`, чтобы порт `587` заменил локальный `1025`.
При старте Spring проверяет соединение и SMTP-аутентификацию; эта проверка не
отправляет письмо. При ошибке подключения backend не стартует. Наличие успешного
соединения ещё не доказывает доставку письма адресату.

Для демонстрации команда выше запускает только БД; Mailpit не требуется.
Если он остался от локальной разработки, его можно остановить без изменения БД:
`docker compose stop mailpit`. Наличие работающего Mailpit не влияет на выбор
почты: он определяется профилями backend.

Frontend запускается как обычно, в другом терминале:

```powershell
cd C:\Users\Sam\Desktop\Backend\frontend
npm.cmd run dev
```

## Проверка доставки

После успешного старта зарегистрируйте тестовую академию на свой доступный email
или запросите восстановление пароля для своего существующего аккаунта.
Проверьте входящие и «Спам», затем откройте ссылку/введите код на сайте.
Одобрение и отказ отправляются очередью; неподтверждённые ранее отправки из очереди
также будут повторены после переключения на реальный SMTP.
`FRONTEND_URL` локально остаётся `http://localhost:5173`; эти ссылки работают на
компьютере с запущенным frontend. Для пользователей с других устройств нужен
доступный им адрес приложения, а для production — его публичный HTTPS-адрес.

Основные ошибки: `535` / `Authentication failed` — неверный пароль приложения или
ограничения Google; timeout / connection refused — проверьте сеть и доступ к порту
587; ошибочный отправитель — проверьте `MAIL_FROM`. SMTP-ошибки не обходите
отключением TLS или проверок сертификата.

Автоматические тесты используют подменённый `JavaMailSender` и не отправляют
письма реальным адресатам. Проверка доставки выполняется отдельно после настройки
учётных данных.

## Production

В `.env.production` используйте те же Gmail SMTP-параметры: `SMTP_HOST=smtp.gmail.com`,
`SMTP_PORT=587`, `SMTP_AUTH=true`, `SMTP_STARTTLS=true`, `SMTP_TEST_CONNECTION=true`.
`MAIL_FROM` укажите явно, `FRONTEND_URL` — адрес развёрнутого сайта.
Production Compose использует профиль `prod` и не читает `backend/.env`.
